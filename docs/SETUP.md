# คู่มือติดตั้งและเริ่มพัฒนาต่อ — PhishMail

เอกสารนี้สำหรับคนที่เพิ่งได้รับโปรเจคนี้มาและต้องการรันให้ขึ้นแล้วพัฒนาต่อ
ทำตามตั้งแต่ต้นจนจบใช้เวลาประมาณ 20–30 นาที ส่วนใหญ่เป็นเวลารอติดตั้ง

---

## ระบบนี้คืออะไร

ระบบตรวจจับอีเมลฟิชชิงด้วยการประมวลผลภาษาธรรมชาติ รองรับทั้งภาษาไทยและอังกฤษ
ประกอบด้วย 4 ส่วนที่ทำงานร่วมกัน

| ส่วน | โฟลเดอร์ | หน้าที่ |
|---|---|---|
| ML pipeline | `ml/` | เตรียมข้อมูล เทรนโมเดล TF-IDF + Naive Bayes แยกตามภาษา |
| Backend API | `backend/` | FastAPI + PostgreSQL รับข้อความอีเมลแล้วตอบคะแนนความเสี่ยง |
| หน้าเว็บ | `frontend/` | Angular 22 build เป็นไฟล์ static แล้วเสิร์ฟจาก backend ตัวเดียวกัน |
| ส่วนขยาย Chrome | `extension/` | ตรวจอัตโนมัติขณะเปิดอ่านอีเมลใน Gmail |

หน้าเว็บกับส่วนขยายเรียก `POST /api/v1/analyze` ตัวเดียวกัน จึงได้ผลลัพธ์ตรงกันเสมอ

## ติดตั้งด้วยคำสั่งเดียว (Windows)

```
git clone https://github.com/PhongamonJutipong/phishing-detection-system.git
cd phishing-detection-system
scripts\setup.bat
```

แค่นี้จบ ไม่ต้องสั่งอะไรต่อ สคริปต์จะทำให้ครบ 10 ขั้น

| ขั้น | ทำอะไร |
|---|---|
| 1 | ตรวจว่ามี Python 3.11 |
| 2 | สร้าง virtual environment ที่ `.venv` |
| 3 | ติดตั้ง dependencies ทั้งหมด |
| 4 | สร้าง `backend\.env` **พร้อมสุ่มกุญแจเข้ารหัสและ token ให้เอง** |
| 5 | เทรนโมเดล (ประมาณ 5 วินาที) |
| 6 | ติดตั้ง dependencies ของ Angular แล้ว build หน้าเว็บ |
| 7 | รันเทสต์ทั้ง 59 ข้อเพื่อยืนยันว่าใช้งานได้จริง |
| 8 | **เปิด Docker Desktop ให้** แล้วรอจนพร้อม |
| 9 | สร้าง image และเริ่มระบบ |
| 10 | รอจนระบบตอบกลับได้ แล้ว**เปิดหน้าเว็บให้อัตโนมัติ** |

จบแล้วต้องเห็นข้อความ `ติดตั้งเสร็จสมบูรณ์` และเบราว์เซอร์เปิดหน้าตรวจสอบอีเมลขึ้นมา

**รันซ้ำได้ปลอดภัย** ไม่เขียนทับ `.venv`, `backend\.env` หรือโมเดลที่มีอยู่แล้ว
และไม่แตะข้อมูลในฐานข้อมูล ถ้ามีอยู่แล้วจะข้ามขั้นตอนนั้นไป

ถ้าอยากติดตั้งอย่างเดียวโดยไม่เริ่มระบบ ใช้

```
scripts\setup.bat -SkipRun
```

> ทำไมต้องมี `.bat` ครอบ `.ps1`: Windows บล็อกการรันสคริปต์ PowerShell เป็นค่าเริ่มต้น
> ไฟล์ `.bat` จัดการเรื่องนี้ให้ จะได้ไม่ต้องจำคำสั่ง `-ExecutionPolicy Bypass`
> และตั้ง codepage ให้แสดงภาษาไทยถูกต้องด้วย

## ติดตั้งเอง (macOS / Linux หรือเมื่อสคริปต์มีปัญหา)

```bash
# 1. virtual environment
python3.11 -m venv .venv
source .venv/bin/activate          # Windows ใช้ .venv\Scripts\activate

# 2. dependencies
pip install -e ".[ml,dev]"      # ติดตั้งโปรเจคแบบ editable พร้อม dependencies ทั้งหมด

# 3. ไฟล์ตั้งค่า
cp backend/.env.example backend/.env
```

เปิด `backend/.env` แล้วเติมสองค่านี้ (สร้างด้วยคำสั่งข้างล่าง)

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"   # ENCRYPTION_KEY
python -c "import secrets; print(secrets.token_urlsafe(24))"                                # ADMIN_TOKEN
```

```bash
# 4. เทรนโมเดล (สำคัญมาก ดูหัวข้อถัดไป)
cd ml
python preprocess.py --include-mock
python train.py
cd ..

# 5. build หน้าเว็บ Angular (ผลลัพธ์ไปอยู่ที่ backend/app/web ซึ่งไม่อยู่ใน git เช่นกัน)
cd frontend
npm ci
npm run build
cd ..

# 6. ยืนยัน
python -m pytest
```

ถ้าข้าม `npm run build` ระบบจะยังรันได้แต่**ให้บริการเฉพาะ API** เปิดหน้าเว็บไม่ได้
และเทสต์ที่ตรวจหน้าเว็บจะถูกข้ามไปโดยอัตโนมัติ

### ทำไมต้องเทรนโมเดลเอง

ไฟล์โมเดล `backend/ml_model/**/*.pkl` **อยู่ใน `.gitignore`** เพราะเป็นผลลัพธ์ที่สร้างใหม่ได้
ไม่ใช่ซอร์สโค้ด การ clone มาเฉย ๆ จะยังไม่มีโมเดล และ backend จะขึ้นไม่ได้

**ไม่ต้องกังวล ใช้เวลารวมประมาณ 5 วินาที** ไม่ได้ใช้ GPU และไม่ต้องดาวน์โหลดอะไรเพิ่ม

ลำดับการทำงาน

```
ml/data/mock_email_dataset.xlsx                    อยู่ใน git (23 KB)
        |
        |  preprocess.py --include-mock            ~4 วินาที
        |  ทำความสะอาด ตัดคำ แยกภาษา แบ่ง 80/20
        v
ml/data/processed/{en,th}/train.csv + test.csv     ไม่อยู่ใน git
        |
        |  train.py                                ~1 วินาที
        |  สร้าง TF-IDF แล้วเทรน Naive Bayes แยกภาษา
        v
backend/ml_model/{en,th}/                          ไม่อยู่ใน git
        ├── tfidf_vectorizer.pkl     ~36 KB   คลังคำและน้ำหนักของแต่ละคำ
        ├── naive_bayes_model.pkl    ~29 KB   ตัวจำแนกที่เรียนรู้แล้ว
        └── model_metadata.json               เทรนเมื่อไร ด้วยข้อมูลกี่แถว ได้ผลเท่าไร
```

backend จะโหลดไฟล์ `.pkl` เหล่านี้ตอนเริ่มทำงาน **ถ้าไม่มี** จะเกิดอาการนี้

- `GET /api/v1/health` ตอบ `"models_loaded": []`
- `POST /api/v1/analyze` ตอบ **503** พร้อมข้อความว่าโมเดลยังไม่พร้อม
- หน้าเว็บกับส่วนขยายจะขึ้นว่าวิเคราะห์ไม่สำเร็จ

เหตุผลที่ไม่เก็บลง git เหมือน `.venv/` คือเป็นไฟล์ไบนารีที่ถูกเขียนใหม่ทั้งไฟล์ทุกครั้งที่เทรน
ถ้าเก็บลง git ประวัติจะบวมเร็วมากโดยไม่ได้ประโยชน์ ในเมื่อสร้างใหม่ได้ใน 5 วินาที

`--include-mock` จะอ่านสองไฟล์รวมกัน

| ไฟล์ | ที่มา | จำนวน |
|---|---|---|
| `ml/data/mock_email_dataset.xlsx` | ชุดจำลองเดิมของโครงงาน | ~230 ฉบับ |
| `ml/data/synthetic_email_dataset.csv` | เขียนขึ้นเองเพื่อขยายคลังคำ ไม่ได้มาจากอีเมลจริง | 120 ฉบับ (ฟิชชิง 60 / ปกติ 60) |

ไฟล์ที่สองครอบคลุมหัวข้อที่ชุดเดิมไม่มี เช่น พัสดุตกค้าง ภาษี ค่าไฟ เงินกู้ การลงทุน
บัตรเครดิต และอีเมลปกติจากบริบทมหาวิทยาลัยกับที่ทำงาน ทำให้คลังคำกว้างขึ้นกว่าเท่าตัว

> **ข้อควรระวังสำคัญ** ทั้งสองไฟล์เป็นข้อมูลที่สร้างขึ้น ไม่ใช่อีเมลจริง
> ใช้ทดสอบว่า pipeline ทำงานได้และลดปัญหาคำที่ไม่เคยเห็นเท่านั้น
> **ห้ามนำค่าความแม่นยำที่ได้ไปรายงาน**

### เทรนด้วยชุดข้อมูลจริง

วางไฟล์ `.csv` หรือ `.xlsx` ที่มีคอลัมน์ข้อความกับป้ายกำกับไว้ใน `ml/data/raw/`
แล้วรัน `preprocess.py` **โดยไม่ใส่** `--include-mock`

ถ้าชุดข้อมูลอยู่นอกโปรเจค (เช่นไฟล์ใหญ่ที่ไม่อยากคัดลอกเข้ามา) ใช้ `--extra-dir` ชี้ไปที่โฟลเดอร์นั้นได้

```bash
cd ml
python preprocess.py --extra-dir "C:/path/to/dataset-folder"
python train.py
```

บน Windows ใช้ `scripts\train.bat` แทนได้ สคริปต์จะใช้ Python ใน `.venv` ให้เอง
แสดงความคืบหน้าแต่ละขั้นบนหน้าจอ และเก็บ log ไว้ที่ `ml\results\train_<วันเวลา>.log`

```bat
scripts\train.bat                                        :: เทรนจากข้อมูลที่ preprocess ไว้แล้ว
scripts\train.bat --extra-dir "C:/path/to/dataset-folder" :: preprocess ใหม่ก่อนแล้วค่อยเทรน
```

> **ระวัง** preprocess จะเขียนทับ `ml/data/processed` ทั้งหมด ถ้าลืมใส่ `--extra-dir`
> ที่ชี้ไปยังชุดข้อมูลใหญ่ ข้อมูลที่ใช้เทรนจะเหลือแค่ชุดจำลองไม่กี่ร้อยแถว

ชื่อคอลัมน์ยืดหยุ่นได้ ระบบรับ `text` / `body` / `content` เป็นข้อความ
และ `label` / `is_phishing` เป็นป้ายกำกับ ค่าป้ายกำกับรับทั้งตัวเลข `1`/`0`
และคำเช่น `spam`/`ham`, `phishing`/`legitimate` แถวที่อ่านป้ายกำกับไม่ออกจะถูกตัดทิ้งพร้อมแจ้งจำนวน

> **ข้อควรระวังเรื่องการตีความ** ชุดข้อมูลสาธารณะจำนวนมากติดป้ายว่า **spam**
> ซึ่งกว้างกว่า **phishing** เพราะรวมโฆษณาที่ไม่ได้หลอกเอาข้อมูลเข้าไปด้วย
> ถ้าเทรนด้วยชุดแบบนั้น โมเดลจะเรียนรู้ว่า "อีเมลไม่พึงประสงค์" มากกว่า "อีเมลหลอกเอาข้อมูล"
> ต้องเขียนกำกับความแตกต่างนี้ไว้ในเอกสารตอนรายงานผล
> ค่าที่ใช้รายงานต้องมาจากชุดข้อมูลจริงประมาณ 18,500 ฉบับ ตามบทที่ 3.3.2
> ถ้ามีชุดข้อมูลจริงให้วางไฟล์ `(text,label)` ใน `ml/data/raw/` แล้วรัน `preprocess.py` โดยไม่ใส่ `--include-mock`

## รันระบบ

เปิด **Docker Desktop** ก่อน รอจนไอคอนวาฬนิ่ง แล้วสั่ง

```bash
docker compose up -d --build
```

ตรวจว่าขึ้นครบ

```bash
docker compose ps
```

ต้องเห็นทั้งสองตัวเป็น `Up ... (healthy)`

### รองรับผู้ใช้พร้อมกันจำนวนมาก

backend รัน uvicorn **4 โปรเซส** เป็นค่าเริ่มต้น ปรับได้ด้วย `WEB_CONCURRENCY`
แต่ละโปรเซสใช้หน่วยความจำราว 550 MB และ connection ฐานข้อมูลได้สูงสุด 15 เส้น

```bash
WEB_CONCURRENCY=2 docker compose up -d      # เครื่องแรมน้อย
```

ถ้าตั้งเกิน 6 โปรเซส ต้องลด `DB_POOL_SIZE` ใน `backend/.env` ไม่งั้น connection รวมจะเกิน 100
ซึ่งเป็นเพดานของ PostgreSQL ผลวัดก่อน/หลังปรับอยู่ใน [decisions.md](decisions.md) ข้อ 13

วัดภาระด้วย `scripts/loadtest.py` **ให้ยิงใส่ฐานข้อมูลทดสอบเท่านั้น** เพราะทุกคำขอถูกบันทึกจริง
และต้องปิด rate limit ของ instance ที่ทดสอบ รายละเอียดอยู่ที่หัวไฟล์ของสคริปต์

```
phishing_backend    Up (healthy)   0.0.0.0:8000->8000/tcp
phishing_postgres   Up (healthy)   0.0.0.0:5433->5432/tcp
```

เปิดใช้งานได้ที่

| ที่อยู่ | คือ |
|---|---|
| <http://127.0.0.1:8000/> | หน้าแรกแนะนำระบบ |
| <http://127.0.0.1:8000/scan> | **หน้าตรวจสอบอีเมล** วางข้อความแล้วกดตรวจ |
| <http://127.0.0.1:8000/dashboard> | หน้าภาพรวมผู้ดูแล ข้อมูลจริงจากฐานข้อมูล กรอกค่า `ADMIN_TOKEN` จาก `backend/.env` ก่อนดู |
| <http://127.0.0.1:8000/register> | สมัครสมาชิก (ไม่บังคับ ตรวจอีเมลได้โดยไม่ต้องมีบัญชี) |
| <http://127.0.0.1:8000/login> | เข้าสู่ระบบ |
| <http://127.0.0.1:8000/account> | ดูข้อมูลบัญชีและลบบัญชี |
| <http://127.0.0.1:8000/privacy> | นโยบายความเป็นส่วนตัว |
| <http://127.0.0.1:8000/docs> | เอกสาร API แบบกดทดลองได้ |

## ติดตั้งส่วนขยาย Chrome

1. เปิด `chrome://extensions`
2. เปิดสวิตช์ **Developer mode** มุมขวาบน
3. กด **Load unpacked** แล้วเลือกโฟลเดอร์ `extension` (โฟลเดอร์ที่มี `manifest.json` อยู่ข้างใน ไม่ใช่โฟลเดอร์โปรเจคชั้นนอก)
4. เปิด <https://mail.google.com> แล้ว **กด F5 รีโหลด** ถ้าเปิดค้างไว้อยู่ก่อนแล้ว
5. ครั้งแรกจะมีหน้าต่างขอความยินยอม กด **อนุญาต**
6. เปิดอ่านอีเมล จะเห็นป้ายระดับความเสี่ยงมุมขวาล่าง

ส่วนขยายทำงานเฉพาะบน `https://mail.google.com` และ**ต้องมี backend รันอยู่** ไม่งั้นจะขึ้นว่าวิเคราะห์ไม่สำเร็จ

## พัฒนาต่อ

### รันแบบ dev (แก้โค้ดแล้วเห็นผลทันที)

รัน Postgres ในคอนเทนเนอร์ แต่รัน backend บนเครื่องเพื่อให้ hot reload ทำงาน

```bash
docker compose up -d postgres
cd backend
../.venv/Scripts/python.exe -m alembic upgrade head     # ครั้งแรก หรือเมื่อ models.py เปลี่ยน
../.venv/Scripts/python.exe -m uvicorn app.main:app --reload
```

> **ต้องสั่งจากโฟลเดอร์ `backend` เท่านั้น** เพราะ `app/config.py` อ่าน `.env` แบบอิงจากโฟลเดอร์ปัจจุบัน
> ถ้าสั่งจากโฟลเดอร์โปรเจคชั้นนอก ระบบจะหา `.env` ไม่เจอแล้ว **กุญแจเข้ารหัสจะกลายเป็นค่าว่างโดยไม่มีข้อความเตือนชัดเจน**
> แต่ `DATABASE_URL` จะยังใช้ค่า default ที่ชี้ Postgres ได้ ทำให้ดูเหมือนทำงานปกติ หาสาเหตุยากมาก

แต่ตอนรันแบบ dev นี้ `DATABASE_URL` ใน `backend/.env` ต้องชี้ `127.0.0.1:5433` ไม่ใช่ `postgres:5432`
(ชื่อ `postgres` ใช้ได้เฉพาะภายในเครือข่ายของ Docker ส่วน `5433` คือพอร์ตที่คอนเทนเนอร์เปิดไว้ฝั่งเครื่อง)

### แก้หน้าเว็บ

## ปัญหาที่เจอบ่อย

### `docker compose up` แล้วขึ้น error หา `backend/.env` ไม่เจอ

ต้องสร้างไฟล์นี้**ก่อน** สั่ง `up` เสมอ เพราะ `docker-compose.yml` อ่านค่าความลับจากไฟล์นี้ผ่าน `env_file`

```bash
cp backend/.env.example backend/.env
```

แล้วเติม `ENCRYPTION_KEY` กับ `ADMIN_TOKEN` (ดูคำสั่งสร้างในหัวข้อติดตั้งเอง)

### `cannot find the file specified` ตอนสั่ง docker

Docker Desktop ยังไม่ได้เปิด เปิดโปรแกรมแล้วรอจนขึ้นว่า Engine running

### backend ขึ้นแล้วแต่ `/api/v1/health` ตอบว่าโมเดลไม่พร้อม

ยังไม่ได้เทรนโมเดล กลับไปทำขั้นตอนเทรนโมเดล แล้วสั่ง `docker compose restart backend`

### เปิดระบบผ่าน Cloudflare Tunnel หรือ reverse proxy แล้วผู้ใช้โดน 429 กันทั้งหมด

ลืมตั้ง `TRUSTED_PROXIES` ใน `backend/.env`

rate limit หาตัวตนผู้เรียกจาก IP ของคู่สนทนาโดยตรง ซึ่งปลอมไม่ได้เพราะต้องทำ TCP handshake สำเร็จ
แต่เมื่อมีตัวคั่น คู่สนทนาจะเป็น**ตัวคั่น**เสมอ ผู้ใช้ทุกคนจึงไปรวมอยู่ในตัวนับถังเดียวกัน
คนเดียวยิงจนเต็มเพดานก็ทำให้คนอื่นใช้ไม่ได้ทั้งหมด หน้า `login`/`register` โดนหนักสุด
เพราะเพดานต่ำกว่ามาก (10 ต่อนาที หารจำนวนโปรเซสแล้ว)

```bash
# cloudflared รันบนเครื่องเดียวกับ backend
TRUSTED_PROXIES=127.0.0.1
REAL_IP_HEADER=CF-Connecting-IP
```

```bash
# cloudflared อยู่ในคอนเทนเนอร์เดียวกับระบบ
TRUSTED_PROXIES=172.16.0.0/12
```

> **ห้ามใส่ `0.0.0.0/0`** เพราะจะกลายเป็นเชื่อ header จากใครก็ได้
> ผู้โจมตีจะใส่ IP สุ่มทุกคำขอแล้วข้าม rate limit ไปทั้งหมด — แย่กว่าไม่ตั้งเลย
> ระบบจะอ่าน header เฉพาะเมื่อคู่สนทนาอยู่ในรายการนี้เท่านั้น

ถ้าตั้งถูกแล้วจะเห็นว่าผู้ใช้แต่ละคนมีเพดานของตัวเอง ตรวจได้ด้วยเทสต์
`pytest backend/tests/test_api.py -k RealClientIp`

### เปิดการเข้าสู่ระบบด้วยบัญชี Google

ค่าเริ่มต้นคือ**ปิด** หน้าเว็บจะไม่แสดงปุ่มและไม่ติดต่อ Google เลย เปิดได้ด้วยขั้นตอนนี้

1. ไปที่ Google Cloud Console → **APIs & Services → Credentials**
2. สร้าง **OAuth client ID** ชนิด **Web application**
3. ใส่ **Authorized JavaScript origins** ให้ตรงกับที่อยู่ที่เปิดหน้าเว็บจริง

   | ตอน | ใส่ |
   |---|---|
   | พัฒนาบนเครื่อง | `http://127.0.0.1:8000` |
   | เปิดผ่าน Cloudflare Tunnel | `https://ชื่อ-tunnel-ของคุณ` |

   > **ไม่ต้องใส่ Authorized redirect URIs** เพราะระบบใช้วิธีตรวจ ID token
   > ไม่ใช่ OAuth code flow จึงไม่มีการ redirect กลับและ**ไม่ต้องใช้ client secret**

4. ใส่ client ID ที่ได้ลง `backend/.env` แล้วรีสตาร์ท backend

```bash
GOOGLE_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com
```

ตรวจว่าเปิดติดแล้ว

```powershell
# ต้องตอบ client ID ที่ตั้งไว้ ไม่ใช่ null
Invoke-RestMethod http://127.0.0.1:8000/api/v1/auth/config
```

**เซิร์ฟเวอร์ต้องออกเน็ตได้** เพื่อดึง public key ของ Google มาตรวจลายเซ็น ถ้าสาธิตแบบออฟไลน์
ช่องทางนี้จะใช้ไม่ได้ แต่การเข้าสู่ระบบด้วยรหัสผ่านและการตรวจอีเมลยังทำงานปกติ

#### กรณีอีเมลนั้นมีบัญชีแบบรหัสผ่านอยู่แล้ว

ระบบจะ**ขอรหัสผ่านเดิมหนึ่งครั้ง**ก่อนผูกบัญชี ไม่ใช่ให้เข้าได้เลย เพราะระบบยังไม่มี
การยืนยันอีเมลตอนสมัคร ใครก็สมัครอีเมลของคนอื่นไว้ก่อนได้ ถ้าปล่อยให้เข้าได้ทันที
เจ้าของอีเมลตัวจริงจะเดินเข้าไปในบัญชีที่คนอื่นตั้งรหัสผ่านไว้ แล้วคนนั้นยังเข้าถึงบัญชีได้ต่อ

หลังผูกแล้วเข้าได้ทั้งสองทาง และรหัสผ่านเดิมยังใช้ได้ตามปกติ

#### บัญชีที่สร้างจาก Google ลบบัญชีอย่างไร

บัญชีกลุ่มนี้ไม่มีรหัสผ่าน จึงยืนยันการลบด้วยการเข้าสู่ระบบ Google อีกครั้งแทน
(`DELETE /api/v1/auth/me` รับทั้ง `password` และ `id_token`)

### จะใส่หน้าคั่นกันบอทของ Cloudflare

ตั้ง WAF Custom Rule ให้ action เป็น **Managed Challenge** แต่**ต้องเว้น `/api/` ไว้**

```
(not starts_with(http.request.uri.path, "/api/"))
```

ถ้าครอบ `/api/` ด้วย ส่วนขยาย Chrome จะใช้งานไม่ได้เลย เพราะมันยิง `fetch`
จาก service worker ซึ่งแก้ JS challenge ไม่ได้ จะได้ HTML ของหน้าคั่นกลับมา
แล้ว `background.js` โยน `SERVER_ERROR` ผู้ใช้เห็น "วิเคราะห์ไม่สำเร็จ" ทุกฉบับ

หน้าเว็บไม่มีปัญหาเพราะผ่านหน้าคั่นแล้วได้คุกกี้ `cf_clearance` มา
คำขอ `api/v1/analyze` ที่ยิงต่อจากหน้านั้นเป็น same-origin คุกกี้ติดไปด้วย

> หน้าคั่นกันบอทได้แค่ตอนโหลดหน้าเว็บซึ่งเป็นไฟล์ static ราคาถูก
> ส่วน `/api/v1/analyze` ที่รันโมเดลยังเปิดอยู่ ถ้าต้องการกันของแพงด้วย
> ให้ตั้ง Rate Limiting ของ Cloudflare ครอบ path นั้นแยก

### ต่อฐานข้อมูลด้วย DBeaver/pgAdmin แล้วขึ้น `password authentication failed`

อาการนี้มักไม่ได้แปลว่ารหัสผ่านผิด แต่แปลว่า**ต่อไปผิดเซิร์ฟเวอร์**

ถ้าเครื่องมี PostgreSQL ติดตั้งบน Windows อยู่แล้ว มันจะจับพอร์ต 5432 ไว้ก่อน
Docker จะเอาพอร์ตนั้นไม่ได้แต่**ไม่ฟ้อง error** และ `docker compose ps` ยังแสดง mapping ตามปกติ
คำขอทุกอันจึงไปโผล่ที่ PostgreSQL ตัวนั้นซึ่งไม่มี role ชื่อ `phishing_user`
และ PostgreSQL ตอบข้อความเดียวกันทั้งกรณีรหัสผิดและกรณีไม่มี role นั้น (กันการเดาชื่อผู้ใช้)

ด้วยเหตุนี้คอนเทนเนอร์จึงเปิดพอร์ต **5433** ฝั่งเครื่อง ไม่ใช่ 5432 ดูว่าใครถือพอร์ตอยู่ได้ด้วย

```powershell
Get-NetTCPConnection -LocalPort 5432,5433 -State Listen |
  ForEach-Object { "{0} pid={1} {2}" -f $_.LocalAddress, $_.OwningProcess, (Get-Process -Id $_.OwningProcess).ProcessName }
```

แยกให้ขาดว่าเป็นปัญหารหัสผ่านหรือปัญหาพอร์ต ด้วยการทดสอบจากในคอนเทนเนอร์ผ่าน TCP
(ถ้าใช้ `psql -U` เฉย ๆ จะต่อผ่าน unix socket ซึ่ง image ตั้ง `trust` ไว้ จึงไม่ได้ตรวจรหัสผ่านเลย)

```powershell
docker exec phishing_postgres psql "postgresql://phishing_user:phishing_pass@127.0.0.1:5432/phishing_db" -c "select 1"
```

ผ่าน = รหัสผ่านถูก ปัญหาอยู่ที่พอร์ตฝั่งเครื่อง

ค่าที่ใช้กรอกใน DBeaver

| ช่อง | ค่า |
|---|---|
| Host | `127.0.0.1` |
| Port | `5433` |
| Database | `phishing_db` |
| Username | `phishing_user` |
| Password | ค่า `POSTGRES_PASSWORD` (ค่าเริ่มต้น `phishing_pass`) |

ถ้าอยากใช้พอร์ตอื่น ตั้ง `POSTGRES_HOST_PORT` ก่อนสั่ง `docker compose up -d`

### ระบบช้าประมาณ 2 วินาทีทุกคำขอบน Windows

ใช้ `localhost` แทน `127.0.0.1` อยู่ — บน Windows การต่อผ่านชื่อ `localhost` จะลอง IPv6 (`::1`) ก่อน
แล้วค่อยถอยมา IPv4 เสียเวลาคงที่ประมาณ 2 วินาทีต่อคำขอ ทั้งที่เวลาประมวลผลจริงอยู่ระดับ 7 มิลลิวินาที

**ใช้ `127.0.0.1` เสมอ** ทั้งในเบราว์เซอร์ ในสคริปต์วัดผล และในค่า `API_ENDPOINT` ของส่วนขยาย
ถ้าวัดผลผ่าน `localhost` จะสรุปผิดว่าไม่ผ่านเกณฑ์ข้อ 1.4.2

### รันสคริปต์ Python แล้วขึ้น `UnicodeEncodeError: 'charmap' codec`

หน้าต่างคำสั่งบน Windows ใช้ cp1252 ซึ่งพิมพ์ภาษาไทยไม่ได้ แก้ด้วยการตั้งตัวแปรก่อนรัน

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

### แก้ไฟล์ในส่วนขยายแล้วไม่เห็นผล

ต้องกดไอคอนรีเฟรชบนการ์ดส่วนขยายใน `chrome://extensions` **แล้วรีโหลดแท็บ Gmail อีกครั้ง**

### เขียนสคริปต์ PowerShell ที่มีภาษาไทยแล้วพาร์สไม่ผ่าน

Windows PowerShell 5.1 อ่านไฟล์ `.ps1` เป็น cp1252 ถ้าไม่มี BOM
ต้องบันทึกไฟล์เป็น **UTF-8 with BOM** ไม่ใช่ UTF-8 เปล่า

รายการงานที่รู้อยู่แล้วว่าต้องทำต่อ เรียงตามความสำคัญ

1. **โมเดลเทรนจากข้อมูลจำลอง** — ต้องหาชุดข้อมูลจริงมาเทรนใหม่ก่อนนำผลไปรายงาน
   ค่าความแม่นยำ `1.0` ใน `ml/results/` ไม่มีความหมาย เพราะข้อมูลน้อยเกินไป
2. **ยังไม่มีข้อมูลภาษาไทยจริง** — มี 2,508 ฉบับแต่เป็นข้อมูลสังเคราะห์ทั้งหมด
   CV ได้ 0.99 เพราะข้อความสร้างจากแม่แบบซ้ำ ๆ ผลทดสอบข้ามแหล่งซึ่งใกล้การใช้งานจริงกว่า
   อยู่ที่ 0.84 – 0.95 (ดู [decisions.md](decisions.md) ข้อ 9)
   **นี่คือช่องว่างที่ใหญ่ที่สุดของโครงงานตอนนี้** การหาชุดข้อมูลไทยเพิ่ม
   ให้ผลมากกว่าการปรับอัลกอริทึมหรือพารามิเตอร์ใด ๆ
3. **ระบบบัญชียังไม่มีการยืนยันอีเมลและลืมรหัสผ่าน** — ต้องมีระบบส่งอีเมลก่อน
   ตอนนี้สมัครด้วยอีเมลที่ไม่ใช่ของตัวเองได้ และหน้าสมัครบอกได้ว่าอีเมลใดมีบัญชีแล้ว (จำกัดด้วย rate limit)
   บัญชียังไม่มีสิทธิ์พิเศษใด ๆ endpoint ผู้ดูแลยังใช้ `X-Admin-Token` เหมือนเดิม
4. **rate limit นับแยกต่อโปรเซส** — login/สมัครหารเพดานด้วยจำนวนโปรเซสแล้ว
   แต่ `/analyze` เพดานจริงเป็นได้ถึง 60 x 4 ครั้งต่อนาทีต่อ IP
   ถ้าต้องการเพดานรวมที่แม่นยำต้องย้ายไปใช้ Redis หรือจำกัดที่ reverse proxy แทน
